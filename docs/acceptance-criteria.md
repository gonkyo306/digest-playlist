# 受入基準：Playlish（お気に入り曲のダイジェスト・プレイリストアプリ）

更新日：2026-10-03
根拠：project-charter.md
表記：各基準のIDは、受入テストケース（acceptance-test-cases.md）の「対応基準」と、ソースコード内のコメントから参照されています。廃止した項目は削除し、番号は振り直していません（欠番があります）。「※補足」は、明記された要望はないが仕様から推定して置いている基準です。

## 0. 前提・対象範囲

### 対象
- 形式：PWA
- 端末：Androidスマホ（Galaxy S26、Android 16、Chrome）
- 回線：Wi-Fi・モバイル回線のどちらでも動作する
- 配信：GitHub PagesでHTTPS公開
- 通信：常にオンライン前提

### 対象外（作らない・確認しない）
- 手動での曲順の並べ替え（FR-2.11の自動アーティスト順ソートは対象内）
- プレイリストの複製
- クラウド保存・端末間の引き継ぎ・バックアップ
- オフライン再生
- ログイン機能
- ストア公開、公開時のApple規約確認（公開を決める段階で実施する）
- 英語表示
- 今後の再生順・再生済み・経過時間バーの表示
- 再生中の再シャッフル操作
- 前の曲へ戻る操作
- iPhone対応（利用者は自分のみ）

### 優先度
- **画面オフ再生は必須要件**とする（NFR-4.5）。PWAで画面オフ・バックグラウンドの連続再生が難しい場合は、クロスフェード（FR-4.7、2秒）の優先度を下げてでも、画面オフ再生を成立させる。
- クロスフェード付きのまま画面オフ再生が実現できない場合の代替案（優先度順）：
  1. クロスフェードなし（曲間は途切れず切り替わる程度）にして、画面オフ再生を維持する
  2. それでも難しい場合は、PWAではなくAndroidネイティブアプリへの切り替えを検討する（要相談）
- **データ消失**：プレイリストは端末内のみに保存され、バックアップもない。ブラウザの永続保存の要求も行わない。ブラウザのデータ削除や、空き容量が少ないときのブラウザの自動削除で、プレイリストが消える可能性がある。許容済みのリスクとして扱う（NFR-3.1〜NFR-3.3）。

## 1. 機能要件

### FR-1 曲の検索
| ID | 基準 |
|---|---|
| FR-1.1 | 検索画面ではキーワードで検索でき、曲名・アーティスト名・アルバム名のいずれかに一致する曲に加えて、ヒットしたアーティスト・アルバムも同じ結果一覧に含めて表示する。検索語はiTunes Search APIにそのまま渡し、APIが返す結果（アルバム名の一致を含む）をそのまま採用する（クライアント側で曲名・アーティスト名・アルバム名の部分一致による絞り込みはしない。APIが返す正当な結果まで除外してしまうため）。検索欄に文字を入力し始めた時点で自動的に検索を開始する（動的検索）。「検索」ボタンは設置せず、確定操作は不要とする。入力のたびに毎回リクエストを送らないよう、入力が一定時間（目安300ms）止まってから検索を実行する（デバウンス） |
| FR-1.2 | 検索結果の各行には、種別（曲／アーティスト／アルバム）に応じた内容を、種別アイコン（FR-1.8）→ジャケット画像（アーティストの行は無し）→名前（曲名／アーティスト名／アルバム名）の順で、左から右へ横並びに表示する（縦に積み上げない）。曲はさらにアーティスト名・アルバム名を、アルバムはさらにアーティスト名を併記する |
| FR-1.3 | 検索対象は日本のストアフロントである |
| FR-1.4 | 試聴音源がない曲は検索結果に表示されない |
| FR-1.5 | 検索結果の各曲（統合検索結果トップの曲、アルバム収録曲一覧の曲のいずれも）は、行自体をタップするとその場で単独に試聴（再生）できる。もう一度タップすると停止する。行ごとの試聴専用アイコンは表示しない。行右端の＋ボタン（FR-1.12）をタップした場合は、追加のみを行い、試聴は開始しない |
| FR-1.6 | プレイリスト再生中に検索結果で試聴すると、プレイリストが一時停止して試聴が再生される。試聴が終わっても、プレイリストは自動再開しない（試聴終了後のミニプレイヤーの扱いはFR-4.18を参照）。試聴の音声が読み込めない・再生できない・端末側で止められた場合は、ミニプレイヤーの試聴中の表示も解除される |
| FR-1.7 | 該当なしの場合は「見つかりません」等の表示が出る（※補足） |
| FR-1.8 | 検索結果の各行の先頭には、種別を示す小さいアイコン（曲＝音符、アーティスト＝人型、アルバム＝円盤）を表示し、曲・アーティスト・アルバムが混在していても見分けられるようにする。ただし、アーティストの行をタップして表示するアルバム一覧画面（FR-1.9）は、全行がアルバムで種別が自明なため、種別アイコンを表示しない |
| FR-1.9 | 検索結果のアーティストの行をタップすると、そのアーティストのアルバム一覧を表示する。アルバムの行をタップすると、そのアルバムの収録曲一覧を表示する。アルバム一覧・収録曲一覧の取得件数の上限は、それぞれ50件である。これらの一覧からは、「戻る」ボタン（アイコンのみ）で1段階ずつ、元のキーワード検索結果（曲・アーティスト・アルバム混在）へ戻れる |
| FR-1.10 | 検索結果には、件数（「〇件見つかりました」等）を表示しない。結果が25件を超える場合、一覧の下端までスクロールすると次の50件が自動で追加読み込みされる（無限スクロール）。読み込みの続きがあることは、視認できる下矢印のガイド表示で案内する。取得件数・試行回数の上限は設けない |
| FR-1.11 | 検索のドリルダウン（FR-1.9）でアルバムを選んだ画面から、そのアルバムの全曲をまとめて再生できる。再生開始前にシャッフルする／しないを選べる（FR-1.14）。この再生はプレイリストへの追加を伴わない、その場限りの一時再生であり、保存されない。再生中の一時停止・再開／次への操作は、プレイリストの再生（第4章）と同じ挙動である。この一時再生中に画面から離れても再生は止まらずに続き、ミニプレイヤー（FR-4.16、FR-4.17）に表示が引き継がれる |
| FR-1.12 | 検索結果の曲（統合検索結果トップの個別の曲、アルバムの収録曲一覧のいずれも）の行の一番右には、小さめの丸いアイコンボタン（＋）を表示する。タップすると、現在の追加先プレイリスト（FR-1.19）へ即座にその曲を1曲だけ追加する（複数選択してまとめて追加する操作は無い）。追加の瞬間、＋アイコンは一瞬チェックアイコンに変化し、その後FR-1.21の表示に切り替わる。現在の追加先プレイリストが無い（プレイリストが1件も無い）場合も、この＋ボタンは常に表示する。その状態でタップすると、その場でプレイリストを作成して追加するダイアログ（FR-1.23）を表示する。ボタンは行本体（試聴のためのタップ領域）とは独立したタップ対象とし、ボタンをタップしても試聴が始まらないようにする（FR-1.5）。行の意匠自体はNFR-5.6を参照 |
| FR-1.14 | アルバム全曲一時再生（FR-1.11）のシャッフル選択は、完全な円形のアイコンボタンのタップで有効／無効を切り替える方式とする。有効なときは、ボタンを強調表示（アクセントカラーで塗る）にして分かるようにする |
| FR-1.15 | アルバムの収録曲一覧画面（FR-1.9）の上部には、Apple Musicのような大きめのジャケット画像（中央寄せ。表示サイズに見合った高解像度の画像を取得し、FR-1.2の検索結果一覧等で使う小さいサムネイルをそのまま拡大表示して粗くしない）→アルバム名・アーティスト名（中央寄せ）→操作ボタン行（完全な円形のシャッフルアイコンボタン＋「再生」という日本語ラベル付きの角丸（ピル型）再生ボタン）を、縦に並べて1回だけ表示する。曲ごとの行は、番号→曲名の順で横並びに表示する（ジャケット・アーティスト名・アルバム名は行ごとには表示しない）。番号は数字のみを表示し、末尾にピリオド（「.」）は付けない（例：「1」であり「1.」ではない）。番号・曲名は行の高さの中で縦中央に表示する。この一覧の行は、ジャケット付きの他の曲一覧（検索結果トップ・プレイリスト詳細。行全体72px）より意図的にやや低くし、行全体の高さを60px（内容エリア44px）とする |
| FR-1.17 | 検索タブとプレイリストタブを行き来しても、それぞれの表示状態（検索結果・ドリルダウンの位置、プレイリスト一覧／詳細画面の表示）が保持される。ただし、既に表示中のタブを再タップした場合は、FR-6.2の通りそのタブのトップ画面にリセットされる |
| FR-1.18 | 検索タブのトップ画面（FR-6.2でリセットされたときの状態）は、検索語・検索結果を含めて何も検索していない完全に空の初期状態である |
| FR-1.19 | 検索タブで検索を実行した後は、画面右上に、現在選択中の追加先プレイリストを、ジャケット画像とプレイリスト名のセットで常時表示する。この表示は、統合検索結果トップ・アーティストのアルバム一覧・アルバムの収録曲一覧など、検索タブ内のどの画面に移動しても（ドリルダウンしても）表示され続ける。初期値は、直前に曲を追加した先のプレイリスト（FR-2.4の「前回追加」の記憶。無ければ一覧の先頭など）とする。追加先選択モーダルで明示的に選んだプレイリストは、他のタブへ移動して検索タブに戻っても、そのまま追加先として表示され続ける。この表示をタップすると、追加先を変更するモーダル（FR-2.4）が開く。プレイリストが1件も無い場合は、この位置には何も表示しない（プレイリストが無い状態での曲追加の導線はFR-1.12・FR-1.23を参照）。ジャケット・プレイリスト名を、1つのカード（背景の角丸ボックス）の中に横一列で収め、タップできることを視覚的に誘導する。カードの右上には「追加先」という小さな文字ラベル（`--muted`色）を絶対配置し、これが追加先を示す表示であることを一目でわかるようにする（カードからはみ出さないよう、十分に小さいフォントサイズにする）。ラベルはカードの余白（padding-top）の中に収まるため、カード自体の高さだけが見出しの高さを決める（見出しの高さはNFR-5.4）。プレイリスト名が表示幅に収まらない場合は、NFR-5.12の自動スクロールで全体を見せる（ジャケットの表示位置は動かさない） |
| FR-1.20 | 検索結果の曲（統合検索結果トップの個別の曲、アルバムの収録曲一覧のいずれも）のうち、画面が表示された時点、または追加先プレイリストを変更した時点で、既に現在の追加先プレイリストに含まれている曲は、行の右端の＋ボタン（FR-1.12）の代わりに、「追加済」という文言の、前回追加ラベル（FR-2.4）と同じ見た目（青いアウトラインのピル型バッジ）を表示する。このバッジはタップしても何も起きない（検索画面からの削除はできない。FR-2.5により削除は編集モード限定）。その場（今回の＋タップ）で追加した曲は、このバッジではなくFR-1.21の表示になる |
| FR-1.21 | 検索結果の曲のうち、その場（今回の＋タップ）で追加した曲は、チェックアイコンへの変化アニメーションの後、そのチェックアイコン（直線のみの意匠。丸背景は付けず、アイコン単体のフラット表示）の右上に、小さい取り消しバッジ（左側だけに小さい切れ目がある、ほぼ一周する反時計回りの巻き戻しアイコン。丸背景を持つ）を重ねて表示する（「追加済」等の文言は表示しない。FR-1.20の静的なバッジとは異なる）。チェックアイコン自体はタップしても何も起きず、取り消しバッジをタップすると、追加を取り消す（プレイリストからその曲を削除する）。取り消しバッジをタップした瞬間、取り消しバッジ自体（チェックアイコンではなく）が反時計回りに1周回転し、一呼吸（約150ms）おいてから、チェックアイコン＋取り消しバッジの表示がフェードアウトした後、＋ボタンの表示（FR-1.12）がフェードインする。この取り消し可能な状態は、同じ画面にとどまっている間は維持されるが、追加先プレイリストを変更したとき、検索タブ内のドリルダウンで画面が切り替わったとき（アーティスト・アルバムへの移動、「戻る」での復帰を含む）、プレイリストタブなど他のタブを開いて検索タブに戻ってきたとき、追加先選択モーダル等のポップアップを開いて閉じたとき、のいずれでも終了し、「追加済」の静的な表示（FR-1.20と同じ見た目）に確定する |
| FR-1.23 | プレイリストが1件も無い状態で、曲の＋ボタン（FR-1.12）をタップすると、その場でプレイリストを作成して曲を追加するためのダイアログを表示する。ダイアログは、他の確認ダイアログと同じ見た目・動き（画面下端からスライドして現れる。NFR-5.10）で、タイトル「プレイリストがまだありません」、2文に分けた（改行を挟む）案内文（「曲を追加するには、まずプレイリストを作成してください。」「作成すると、この曲がそのまま追加されます。」）、プレイリスト名の入力欄、「キャンセル」「作成して追加」の2つのボタンで構成する。プレイリスト名が空の間は「作成して追加」を無効にする。「作成して追加」をタップすると、入力した名前で新しいプレイリストを作成し、それを新たな追加先（FR-1.19）とした上で、タップした曲をそのプレイリストへ1曲だけ追加する（FR-1.12と同じ追加処理）。右上の追加先表示のジャケットには、追加した曲のジャケットが反映される（FR-2.10）。この曲は、取り消し可能な表示（FR-1.21）ではなく、最初から「追加済」の静的な表示（FR-1.20と同じ見た目）に確定する。「キャンセル」または画面外タップで閉じた場合は、プレイリストを作成せず、＋ボタンの表示に戻る |
| FR-1.24 | アルバムの収録曲一覧画面（FR-1.15）の操作ボタン行には、シャッフル・再生ボタンの右に、丸いアイコンボタン（プレイリスト追加アイコン、アクセントカラー。背景はシャッフルボタンと同じカード付きの丸。タップ領域は44px以上）の「全曲追加」ボタンを置く。タップすると、そのアルバムの全曲を、現在の追加先プレイリスト（FR-1.19）へまとめて追加する。既に追加先にある曲は飛ばし、追加先に無い曲だけを、収録順に追加する（FR-2.6）。追加すると、アルバムの各曲の行は、静的な「追加済」バッジ（FR-1.20と同じ見た目）になり（各行の＋とバッジ、全曲追加ボタンのアイコンの切り替えは、いずれもフェードアウトしてからフェードインで差し替わる。約0.2秒ずつ）、画面下部（ミニプレイヤー・タブバーの上）に「N曲を「○○」に追加しました」と［取り消し］を表示する（約6秒で消える。画面を移動すると消える）。［取り消し］をタップすると、その操作で追加した曲だけを追加先から削除する（元から追加先にあった曲は残る。各行のバッジが＋に戻る切り替えと、ボタンのアイコンが戻る切り替えは、追加時と同じフェードアウト→フェードイン）。追加先に未追加の曲が残っているときは、ボタンのラベル（読み上げ用）が「残りN曲を「○○」に追加」になり、全曲が追加済みのときは、チェックアイコンで薄く表示して押せない。プレイリストが1件も無いときは、曲の＋ボタン（FR-1.23）と同じ、その場で作成するダイアログ（案内文は「作成すると、このアルバムの全曲がそのまま追加されます。」）を表示し、作成すると全曲を追加する。キャンセルした場合は何も作成・追加しない |

### FR-2 プレイリストの管理
| ID | 基準 |
|---|---|
| FR-2.1 | 名前を付けて、複数のプレイリストを作成できる。作成は、一覧画面右上の「＋」ボタンから開くプレイリスト作成画面（FR-2.17）で行う（一覧画面にインラインの名前入力欄は無い。一覧画面の入力欄はプレイリスト名検索用。FR-2.18参照） |
| FR-2.2 | プレイリストの名前を変更できる。詳細画面の右上（戻るボタンとは反対側）の「編集」ボタン（FR-2.14）をタップして編集モードに入ると、見出しの部分がその場で編集できる状態になる。「保存」で確定するまでは変更されない（一覧画面の各行には名前変更の導線は配置しない） |
| FR-2.3 | プレイリストを削除できる。削除前に確認が表示される。確認メッセージは「「〇〇」を削除しますか？」「この操作は取り消せません。」の2行に分けて表示する。削除ボタンは、プレイリスト詳細画面の右上（編集ボタンと並べて）に配置する（一覧画面の各行には配置しない）。編集モードには含めず、通常時から常に操作でき、タップすると即座に確認ダイアログが表示される。確認ダイアログの「削除する」ボタンの背景色は、`--danger`色ではなく、編集モードのマイナスボタン（FR-2.14）と同じ鮮やかな赤（`#ff3b30`）を用いる |
| FR-2.4 | 検索タブ（FR-6.1）で、現在の追加先プレイリスト（FR-1.19）をタップして変更する際、追加先のプレイリストを選ぶモーダルが表示される。モーダルには全プレイリストを一覧表示し、各行にそのプレイリストのジャケット画像（FR-2.10の代表画像と同じもの）を、プレイリスト名・曲数と並べて表示する。プレイリスト名の文字は、曲数の表示より少し大きく表示する。直前に追加した先のプレイリストがあれば、その行の一番右に小さなラベル（「前回追加」）を付けて分かるようにする（一覧内での並び順は変更しない）。選ぶ操作は1タップで、別画面や2段階の選択は挟まない。選ぶと、そのプレイリストが新しい追加先になり、モーダルが閉じてFR-1.19の表示が切り替わる。プレイリスト詳細画面から検索へ遷移する導線はない。モーダルの右上には、その場で新しいプレイリストを作成できる＋ボタンを配置する（色はアクセントの青ではなく、他のアイコンと同じ文字色（ダークテーマでは白）。タップするとプレイリスト作成画面（FR-2.17）へ遷移する。キャンセルで戻ると、作成されず、追加先も変わらない）。作成すると、そのプレイリストが新しい追加先になり、モーダルが閉じて元の画面に戻る。本モーダルは追加先ヘッダー（FR-1.19）からのみ開き、特定の曲の指定は無いため、曲の自動追加は行わない |
| FR-2.5 | プレイリストから曲を削除できる。削除は編集モード（FR-2.14）中のみ行え、通常時は曲の行に削除の導線を表示しない |

### FR-3 保存
| ID | 基準 |
|---|---|
| FR-3.1 | プレイリストは端末内に保存され、ログインなしで利用できる |
| FR-3.2 | 保存するのは曲の識別情報のみで、曲名・ジャケット等は表示時に最新情報を取得する |
| FR-3.3 | 取得できなくなった曲（配信終了・試聴音源なし等）があっても、プレイリスト全体の表示・再生は失敗せず、その曲は再生時にスキップされ、利用者に分かる形で示される（※表示は補足）。端末がオンラインなのに1曲だけ取得できない場合も同様に、その曲をスキップして次へ進む |

### FR-4 再生
| ID | 基準 |
|---|---|
| FR-4.1 | プレイリストの詳細画面を開き、再生操作をすると連続再生が始まる。また、プレイリスト一覧の各行の再生ボタン（FR-2.9）と、「前回のプレイリスト」カードの再生ボタン（FR-2.20）からも、詳細画面を開かずに再生を始められる（全曲をシャッフルONで再生する） |

| FR-4.3 | 全曲が一巡するまで、同じ曲は再生されない |
| FR-4.4 | 全曲を一巡すると、自動的に停止する（自動的な再シャッフル・再生の継続は行わない）。停止すると、ミニプレイヤー（FR-4.16）は一時停止と同じ表示になり、次への操作は非活性化される。この停止の挙動は、プレイリスト本編の再生にも、アルバムの一時再生（FR-1.11）にも共通して適用される |
| FR-4.5 | 各曲は試聴音源（約30秒）を最後まで再生する |

| FR-4.7 | 曲の切り替わりは2秒のクロスフェードで行われ、無音区間が生じない（優先度：中。NFR-4.5の画面オフ再生と両立しない場合は、クロスフェードを省略する） |
| FR-4.8 | 一時停止と再開ができる。再生・一時停止の表示（ミニプレイヤー、ロック画面・通知）は、端末側の都合（他アプリの音声・通話・イヤホンの切断・AudioContextの中断・音声のエラー等）で実際の再生が止まった場合も、実際の状態に合わせて一時停止の表示に切り替わる。停止中なのに再生中の表示になることはなく、停止後に再生操作をすると実際に音が出て再開する |
| FR-4.9 | 次の曲へスキップできる |
| FR-4.11 | 再生中の曲のジャケット・曲名・アーティスト名は、常時表示のミニプレイヤー（FR-4.16）に表示される |
| FR-4.12 | 画面を消した状態や他アプリ使用中も連続再生が続き、ロック画面・通知から一時停止・スキップ等の操作ができる（前の曲へ戻る操作は提供しない）。再生中に端末のステータスバー（Androidの左上）・通知に表示される小さいアイコンは、プレイリストタブと同じ2連符（白・背景透過のモノクロアイコン。`manifest.json`に`monochrome`として登録）とする。ホーム画面に追加したアプリ（WebAPK）の更新後に反映される |
| FR-4.13 | 再生中に端末がオフラインになったら一時停止し、通信が復帰したら再開できる（1曲だけ取得できない場合はFR-3.3のスキップに従う） |
| FR-4.14 | 曲が1曲のみのプレイリストは、その曲を繰り返し再生する。曲が0件のプレイリストは再生操作ができない（※補足） |
| FR-4.15 | 再生中に3曲連続で曲の取得に失敗した場合は、再生を止めてエラーを表示する（3曲未満の連続失敗は、FR-3.3のスキップに従う） |
| FR-4.16 | 曲の再生（プレイリスト再生・アルバムの一時再生、FR-1.11）が始まると、詳細画面／アルバム画面を見ているかどうかに関わらず、常に画面下部に常時表示のミニプレイヤーが表示される。ミニプレイヤーには、再生中の曲のジャケット・曲名・アーティスト名と、一時停止/再開・次への操作アイコン（テキストラベルなし。FR-5.3）を備える。検索タブでの試聴（FR-1.6）も、同じミニプレイヤーに表示・操作できる。「次へ」ボタンは、複数曲を連続再生している場合（プレイリスト再生・アルバムの一時再生）は活性化し、単体の試聴中は非活性化（グレーアウト）する。曲名が表示幅に収まらない場合は、NFR-5.12の自動スクロールで全体を見せる（ジャケット・操作アイコンの表示位置は動かさない）。曲を切り替えるときも、ミニプレイヤーは一瞬消えたりジャケット・曲名が空白になったり、位置がずれたりせず、新しい曲の表示へ切り替わる（再生の読み込み待ち中も、その曲を再生中として表示する）。ミニプレイヤーの上下の余白は同じ大きさに見える（下の余白だけがタブバーに隠れない） |
| FR-4.17 | ミニプレイヤーをタップすると、再生中のプレイリスト詳細画面（アルバムの一時再生中はその再生元の画面）に遷移する。検索タブでの試聴中は、遷移先の画面がないためタップしても何も起きない |
| FR-4.18 | 検索タブでの試聴（FR-1.6）が終了すると、ミニプレイヤーは非表示になる。一時停止していた本編（プレイリスト再生・アルバムの一時再生）の表示には自動的に戻さない。本編を再開したい場合は、利用者が該当のプレイリスト詳細画面／アルバム画面に戻って再生操作をする |

### FR-5 画面表示
| ID | 基準 |
|---|---|
| FR-5.1 | ダーク／ライトのテーマが、端末の設定に自動で追従する |
| FR-5.2 | 表示言語は日本語のみである |
| FR-5.3 | 再生・一時停止・次へ（メインの再生操作、ミニプレイヤー）を含め、曲の追加・試聴・削除・戻る・編集のキャンセル／保存・プレイリストの編集・削除など、すべての操作ボタンは、視覚的なアイコン（SVG）のみで表示し、テキストラベルは併記しない（ただし、確認ダイアログ内のボタンと、「再生」ピル型ボタンは日本語ラベル付き） |
| FR-5.4 | 画面には、操作の手順を説明する案内文（例：「〇〇タブから追加できます」）を常時表示しない。一覧が空のときの表示は、状態のみを伝える簡潔な文言（例：「まだありません」）にとどめる。曲の＋ボタンをタップした時点で表示するダイアログ（FR-1.23）内の説明文は、常時表示の案内文ではなく、ユーザー自身の操作に応じて一時的に出るものであるため、この方針の対象外とする |

### FR-6 画面構成
| ID | 基準 |
|---|---|
| FR-6.1 | アプリ全体は「プレイリスト」「検索」の2つのタブで切り替えられる。「プレイリスト」タブにはプレイリスト一覧・詳細画面が、「検索」タブには統合された曲検索（曲・アーティスト・アルバムの混在表示とドリルダウンを含む、FR-1.1〜FR-1.2、FR-1.5〜FR-1.15）が表示される。プレイリストタブ・検索タブを行き来しても、それぞれの表示状態は保持される（FR-1.17）。各タブのボタンには、日本語ラベル（「プレイリスト」「検索」）の上にアイコンを添える（背景のカード等は付けず、アイコン単体。表示サイズは24px、2つのタブでアイコン＋ラベルの高さが揃う）。検索タブのアイコンは虫眼鏡。プレイリストタブのアイコンは、2連符（八分音符2つ・連桁）を丸みのある塗りつぶしの四角で囲み、その右上奥に同じ形の少し小さい影を2枚重ねて（各層の間に細い区切り線を入れて層の境目が分かるように）、複数のプレイリストが連なっている様子を表す。四角の色は他のアイコンと同じ（非選択＝薄いグレー、選択中＝青）で、2連符はダークテーマでは黒、ライトテーマでは白（選択状態によらず固定）。連桁は緩やかな右肩上がりで、2本の縦棒はほぼ同じ長さ（右の音符がわずかに高い）、縦棒は連桁からはみ出さず、2連符は四角の中央に配置する。アプリの起動直後や端末のスクロール端で、画面下部に青い線・帯が表示されず、背景が白くちらつかず、タブバーの領域が最初から表示される |
| FR-6.2 | 既に表示中のタブを再度タップすると、そのタブのトップ画面にリセットされる。「プレイリスト」タブは一覧画面（詳細画面を表示していた場合は一覧に戻す）、「検索」タブは検索語・検索結果も含めて完全に空の初期状態（FR-1.18）に戻す。他方のタブから切り替えてきた場合（再タップではない場合）は、FR-1.17の通り従来の表示状態を保持する |
| FR-6.3 | OSの「戻る」操作（Androidの戻るジェスチャー・戻るボタン、ブラウザの戻るボタン等）でも、画面内の「戻る」操作と同等にアプリ内を1段階ずつ戻れるようにする。対象は、(1) 検索タブのドリルダウン（統合検索結果トップ→アーティストのアルバム一覧→アルバムの収録曲一覧）、(2) プレイリスト詳細画面（一覧⇔詳細）、(3) プレイリスト詳細画面の編集モード（編集モード中に戻る操作をすると、キャンセルと同じ扱いで通常モードに戻る）、(4) 開いているダイアログ・モーダル（削除確認、追加先選択モーダル、プレイリスト作成画面等。戻る操作で、キャンセル・閉じる操作と同じ扱いになる。ダイアログ・モーダルが開いている間の戻る操作は、その下の画面の遷移よりも優先する）。タブの切り替え自体（「プレイリスト」タブ⇔「検索」タブの行き来）は対象に含めない。各タブのトップ画面（プレイリスト一覧、検索タブの初期状態）で戻る操作をした場合、アプリ内にそれ以上戻る対象が無いため、ブラウザ・OS標準の動作（アプリを離脱する等）に委ねる |

## 2. 非機能要件

### NFR-1 性能
| ID | 基準 |
|---|---|
| NFR-1.1 | 検索を実行してから3秒以内に結果が表示される（Wi-Fi・モバイル回線のどちらでも） |
| NFR-1.2 | プレイリスト詳細画面で再生操作をしてから、3秒以内に最初の曲の再生が始まる |
| NFR-1.3 | 曲の切り替わりで無音区間が生じない（クロスフェードで連続する。NFR-4.5により省略される場合は対象外） |

### NFR-2 信頼性・継続再生
| ID | 基準 |
|---|---|
| NFR-2.1 | 20曲のプレイリストを、最初から最後まで途中で止まらずに再生できる（所要時間の目安：クロスフェードありの場合は約9分22秒＝20曲×30秒−クロスフェード19回×2秒、クロスフェードを省略した場合は約10分＝20曲×30秒） |
| NFR-2.2 | 通信断（端末のオフライン）は許容される例外とし、FR-4.13の動作（一時停止→復帰後に再開）に従う |
| NFR-2.3 | 通信エラー時（検索・曲情報の取得）は、失敗したことが利用者に分かる表示が出て、アプリが操作不能にならない（※補足） |

### NFR-3 データの永続性
| ID | 基準 |
|---|---|
| NFR-3.1 | アプリ（ブラウザ）を閉じて開き直しても、作成したプレイリストとその曲が残っている |
| NFR-3.2 | 端末を再起動しても、プレイリストが残っている（※補足） |
| NFR-3.3 | ブラウザの永続保存の要求は行わない（プレイリストが消える可能性は許容済み） |
| NFR-3.5 | 旧版（保存先の内部名称が「medleys」だった版）で保存済みのプレイリストのデータは失われず、そのまま引き継がれる |
| NFR-3.6 | プレイリストにアップロードした画像（FR-2.17、FR-2.19）は、端末のストレージ消費を抑えるため、保存前に自動でリサイズ・圧縮する（長辺800px程度を上限にアスペクト比を保ってリサイズし、JPEG形式で圧縮して保存する）。元の画像そのものは保持しない |
| NFR-3.7 | プレイリストに曲を追加する際、iTunes Search/Lookup APIのレスポンスに含まれるアルバム内トラック番号（`trackNumber`）を、曲データの一部として保存する（FR-2.11のアルバム・収録順まとめの並び替えに用いる）。レスポンスにトラック番号が含まれない場合は保存しない（該当曲はFR-2.11の追加順で並ぶ）。トラック番号を持たない既存の曲は、そのままFR-2.11の追加順の対象として扱う（遡っての再取得・移行は行わない） |

### NFR-4 互換性・動作環境
| ID | 基準 |
|---|---|
| NFR-4.1 | 利用者本人のAndroid端末（Galaxy S26、Android 16、Chrome）で、FR・NFRのすべてが動作する |
| NFR-4.2 | PWAとしてホーム画面に追加でき、アプリのように起動できる（※補足）。アプリ名は「Playlish」とする（`manifest.json`の`name`・`short_name`、`index.html`の`<title>`） |
| NFR-4.3 | オンライン環境で動作する。オフラインでの動作は保証しない |
| NFR-4.4 | GitHub PagesにHTTPSで配置され、URLからアクセスできる |
| NFR-4.5 | 画面オフ・バックグラウンドの状態でも、NFR-2.1の20曲の連続再生が最後まで続く（必須要件）。クロスフェード（FR-4.7）は、画面オフ再生の実現を優先し、必要なら省略してよい |

### NFR-5 使い勝手
| ID | 基準 |
|---|---|
| NFR-5.1 | 通勤中・家事の合間に片手で使える画面構成である（スマホ縦画面で、主要操作がすべて画面内に収まる）（※補足） |
| NFR-5.2 | アイコンのみのボタン（FR-5.3）も、指でのタップに十分な大きさ（目安44px四方）のタップ領域を確保する |
| NFR-5.3 | 確認・選択のダイアログ（プレイリストの削除確認、追加先の選択モーダル等）は、操作を連打しても多重に表示されない |
| NFR-5.4 | プレイリストタブ・検索タブの見出し・入力欄など、両タブで共通する要素の表示位置（高さ）は揃っている。タブを切り替えたときに、画面の見た目が上下にずれて見えない。見出しの高さ（`.screen-header`のmin-height）は、検索タブの追加先カード（FR-1.19）の実高さに合わせた48pxで、全画面共通とする |
| NFR-5.5 | 追加先のプレイリストを選ぶモーダル（FR-2.4）で、プレイリスト名の文字は、一覧の他の要素（曲数の表示等）よりも少し大きく表示し、読みやすくする |
| NFR-5.6 | アプリ内のすべての一覧行（プレイリスト一覧、アーティスト一覧、アルバム一覧、検索結果の曲一覧、アルバム収録曲一覧、プレイリスト詳細の曲一覧、追加先選択モーダルの一覧を含む）は、Apple Musicのように、背景色付きの角丸カードと行間の余白ではなく、行の背景を画面の背景と同化させ、各行の下端に1本の細い横線（区切り線）を全幅で表示する意匠で統一する。一覧の先頭行の上と最後の行の下にも同じ区切り線を表示し、一覧全体が上下を区切り線で囲まれた形になる。行内の＋／マイナスボタン等の操作要素は、行の右端に配置する（ジャケット画像・番号などの左端の位置は揃える） |
| NFR-5.7 | アプリ内のすべてのアイコンのみの操作ボタン（戻る・編集・削除、ミニプレイヤーの再生・一時停止／次へ、プレイリスト作成画面・編集モードのキャンセル／保存等を含む）は、背景色付きの角丸ボックス（カード）を持たず、アイコン単体で表示する（タップ領域自体はNFR-5.2の44px四方を維持する）。削除（ゴミ箱）アイコンは、`--danger`等の特別な着色をせず、他の通常のアイコンと同じプレーンな色で表示する。隣り合うアイコンボタンは、各タップ領域が隣接して並ぶ（プレイリスト詳細の「編集」と「削除」は間隔なしで並べる）。**例外**：シャッフル切り替えボタン（`.shuffle-btn`）とアルバムの全曲追加ボタン（`.add-all-btn`、FR-1.24）は対象外とし、背景色付きの丸（カード）を維持する（シャッフルはON／OFFの状態を持つトグルボタンであり、全曲追加はシャッフル・再生ボタンと並ぶ操作として、視認性を優先するため）。一覧の行の再生ボタン（FR-2.9）は、枠線付きの丸とする |
| NFR-5.8 | ミニプレイヤーの操作アイコン（再生／一時停止・次へ）は、他画面のアイコン単体表示（NFR-5.7）より一回り大きく表示する（目安：20px→26px）。タップ領域自体はNFR-5.2（44px四方）を維持し、アイコンの見た目の大きさのみを拡大する |
| NFR-5.9 | 曲一覧の項番（アルバム収録曲一覧の番号、FR-1.15）は、曲名との間隔を広めに取り、番号を左寄せで表示する |
| NFR-5.10 | アプリ内のポップアップ（確認・入力ダイアログ、追加先選択モーダル、プレイリスト作成シートなど、`.dialog-overlay`／`.dialog-box`を共有する全てのポップアップ）は、画面中央へのフェード表示ではなく、画面下端から上へスライドして現れ、閉じるときは下へスライドして消えるアニメーションで表示する（背景のオーバーレイは暗転のフェードのみとする） |
| NFR-5.11 | アプリ内のすべての入力欄（検索ボックス、プレイリスト作成画面の名前入力欄、編集モードのプレイリスト名を含む）は、フォーカス時にブラウザ既定の白いアウトライン（フォーカスリング）を表示せず、アクセントカラーの枠線に差し替える |
| NFR-5.12 | 一覧の行・ミニプレイヤー・追加先表示のタイトル（プレイリスト一覧のプレイリスト名、プレイリスト詳細・アルバム収録曲一覧・検索結果の曲名、検索結果のアルバム名・アーティスト名、追加先選択モーダルのプレイリスト名、追加先カード（FR-1.19）、前回のプレイリストカードのプレイリスト名（FR-2.20）、ミニプレイヤーの曲名）は、1行で表示し（折り返さない）、表示幅に収まらない場合は、省略記号ではなく自動スクロールで全体を見せる。動きは、「初期表示のまま約1秒静止 → はみ出した文字が全部左に流れ切って何も見えなくなるまで流す → 初期表示に戻す」を繰り返す（戻るたびに毎回約1秒静止してから流し直す）。速さは1秒あたり約40px（1周の流す時間は最短3秒）。表示幅に収まるタイトルは静止表示のままで、行の高さは変わらない。タブを切り替えたとき、画面を描き直したときは、判定をやり直す（複数のスクロールが重なって表示されない） |
| NFR-5.13 | 画面上部の見出し行（プレイリスト一覧の見出しと＋ボタン、検索タブの見出しと追加先プレイリスト（FR-1.19）、アルバム収録曲一覧・アーティストのアルバム一覧の戻るボタンと追加先プレイリスト、プレイリスト詳細の戻る・編集・削除（編集モード中はキャンセル・保存）のアイコン）は、画面を下へスクロールしても、画面の上端に固定して表示し続ける（下の行は見出し行の下へ隠れる）。スクロール前の見出し行の表示位置・高さは、固定表示にしても変わらない（NFR-5.4） |

### NFR-6 セキュリティ・プライバシー・保守
| ID | 基準 |

| NFR-6.1 | 会員登録・ログインが不要である |
| NFR-6.2 | 外部への通信は、曲の検索・情報取得（Apple提供の公開API）と試聴音源の取得のみである（アプリ自体の配信元（GitHub Pages）への通信は除く）（※補足） |

## 3. 受入テストの実施条件
- 端末：利用者本人のGalaxy S26（Android 16）、Chrome（最新版）
- 回線：Wi-Fiとモバイル回線の両方
- 曲データ：20曲以上のプレイリストを用意して確認する（NFR-2.1、FR-4.3、FR-4.4）
- 早期確認：画面オフ・バックグラウンドでの連続再生は必須要件（NFR-4.5）。PWAの制約に左右されるため、最初に検証する。クロスフェード付きで通らない場合は、クロスフェードなしで画面オフ再生が成立するかを確認する
- 曲データ：検索結果が26件以上になるキーワード（FR-1.10）、アルバムを複数持つアーティスト・複数曲を持つアルバム（FR-1.9、FR-1.11）、アーティスト名が異なる曲を含むプレイリスト（FR-2.11の並び順確認用）、検索結果に曲・アーティスト・アルバムが混在するキーワード（FR-1.8、FR-1.9）、追加先プレイリストを複数（FR-2.4）を用意する
- 曲データ：曲が0件のプレイリスト（FR-2.10のプレースホルダー画像確認用）、複数曲のプレイリスト（FR-2.13の行タップ再生開始位置の確認用）を用意する
- NFR-3.5（既存データの移行）の確認：旧版で作成済みのプレイリストが残っている端末（実機）で、アプリを更新後に開き、プレイリストが消えていないことを確認する
