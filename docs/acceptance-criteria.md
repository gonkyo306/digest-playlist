# 受入基準：お気に入り曲のダイジェスト・プレイリストアプリ

作成日：2026-09-27
更新日：2026-09-27（change-request-form.md CR-001〜CR-008の仕様確定を反映）
根拠：project-charter.md、spec-questions.md（各質問の回答）、change-request-form.md（CR-001〜CR-008）
表記：括弧内は根拠となる質問番号（例：4-3）またはCR番号（例：CR-001）。「※補足」は回答に明記がなく、仕様から推定して追加した基準です（不要なら削除してください）。CR番号が根拠にある基準は、初回リリース後の改修要望として追加・変更されたものです。

## 0. 前提・対象範囲

### 対象（今回の受入対象）
- 形式：PWA（1-1）
- 端末：Androidスマホ（Galaxy S26、Android 16、Chrome）（1-2、10-2）
- 回線：Wi-Fi・モバイル回線のどちらでも動作する（測定条件の質問より決定）
- 配信：GitHub PagesでHTTPS公開（10-3、11-1）
- 通信：常にオンライン前提（1-3）

### 対象外（作らない・確認しない）
- 手動での曲順の並べ替え（憲章 決定事項。FR-2.11の自動アーティスト順ソートは対象内）
- プレイリストの複製（3-2）
- クラウド保存・端末間の引き継ぎ・バックアップ（5-1、5-2）
- オフライン再生（1-3）
- ログイン機能（7-1）
- ストア公開、公開時のApple規約確認（7-2：公開を決める段階で実施）
- 英語表示（6-4）
- 今後の再生順・再生済み・経過時間バーの表示（4-6）
- 再生中の再シャッフル操作（4-5）
- iPhone対応（利用者は自分のみ）

### 優先度
- **画面オフ再生は必須要件**とする（NFR-4.5）。PWAで画面オフ・バックグラウンドの連続再生が技術的に難しい場合は、クロスフェード（FR-4.7、2秒）の優先度を下げてでも、画面オフ再生を成立させる。
- クロスフェード付きのまま画面オフ再生が実現できない場合の代替案（優先度順）：
  1. クロスフェードなし（曲間は途切れず切り替わる程度）にして、画面オフ再生を維持する
  2. それでも画面オフ再生が technically 難しい場合は、PWAではなくAndroidネイティブアプリへの切り替えを検討する（1-1の見直し。要相談）
- 最小版の段階で、画面オフ・バックグラウンドでの連続再生を最初に検証する（FR-4.7、FR-4.12、NFR-4.5、第3章）。
- **データ消失**：プレイリストは端末内のみに保存され、バックアップもない（5-1、5-2）。ブラウザの永続保存の要求も行わない（10-1）。ブラウザのデータ削除や、空き容量が少ないときのブラウザの自動削除で、プレイリストが消える可能性がある。許容済みのリスクとして扱う（NFR-3.1、NFR-3.2）。

## 1. 機能要件

### FR-1 曲の検索
| ID | 基準 | 根拠 |
|---|---|---|
| FR-1.1 | 「フリーワード検索」モードでは、曲名・アーティスト名・アルバム名のいずれかに一致するキーワードで検索でき、結果が一覧表示される。検索語はiTunes Search APIにそのまま渡し、APIが返す結果（アルバム名の一致を含む）をそのまま採用する。クライアント側で曲名・アーティスト名・アルバム名の部分一致を条件に絞り込むと、APIが返す正当な結果まで除外してしまうことが実装時の動作確認で判明したため、絞り込みは行わない（※実装時に変更） | 2-1、CR-001（アルバム名を対象に追加） |
| FR-1.2 | 各検索結果に、ジャケット・曲名・アーティスト名・アルバム名が表示される | 2-2 |
| FR-1.3 | 検索対象は日本のストアフロントである | 2-4 |
| FR-1.4 | 試聴音源がない曲は検索結果に表示されない | 2-5 |
| FR-1.5 | 検索結果の各曲を、その場で試聴（再生・停止）できる | 2-3 |
| FR-1.6 | プレイリスト再生中に検索結果で試聴すると、プレイリストが一時停止して試聴が再生される。試聴が終わっても、プレイリストは自動再開しない | 9-1 |
| FR-1.7 | 該当なしの場合は「見つかりません」等の表示が出る（※補足） | ― |
| FR-1.8 | 検索画面には「フリーワード検索」（FR-1.1）と「段階検索」（FR-1.9）の2つのモードがあり、検索画面内のタブで切り替えられる。この切替はFR-6.1の画面全体のタブ構成とは別のものである | CR-001 |
| FR-1.9 | 段階検索モードでは、アーティスト名で検索してアーティストを選ぶと、そのアーティストのアルバム一覧が表示される。アルバムを選ぶと、そのアルバムの曲一覧が表示される。アーティスト検索・アルバム一覧・曲一覧の各ステップの取得件数の上限は50件である | CR-001 |
| FR-1.10 | フリーワード検索（FR-1.1）の結果が25件を超える場合、一覧の下端までスクロールすると、次の50件が自動で追加読み込みされる（無限スクロール）。取得件数・試行回数の上限は設けない | CR-005 |
| FR-1.11 | 段階検索（FR-1.9）でアルバムを選んだ画面から、そのアルバムの全曲をまとめて再生できる。再生開始前にシャッフルする／しないを選べる。この再生はプレイリストへの追加を伴わない、その場限りの一時再生であり、保存されない。再生中の一時停止・再開／次へ／前への操作は、プレイリストの再生（第4章）と同じ挙動である。この一時再生中に画面から離れても再生は止まらずに続き、ミニプレイヤー（FR-4.16、FR-4.17）に表示が引き継がれる | CR-007 |
| FR-1.12 | 検索結果（フリーワード検索・段階検索の曲一覧）の各曲にチェックボックスが表示され、選択した曲を「追加候補リスト（カート）」に一時的に保持できる。カートの内容はブラウザに保存され、アプリを閉じて開き直しても保持される。カートに入れられる曲数の上限はない | CR-008 |
| FR-1.13 | カートから、追加先のプレイリストを選ぶモーダル／画面を経て、選択した曲をまとめてプレイリストに追加できる（FR-2.4）。追加された曲はカートから削除される。すでにそのプレイリストに追加済みの曲は、カートのチェックボックスが選択できない状態（グレーアウト）で表示される。重複の判定はFR-2.6に準ずる | CR-008 |

### FR-2 プレイリストの管理
| ID | 基準 | 根拠 |
|---|---|---|
| FR-2.1 | 名前を付けて、複数のプレイリストを作成できる | 3-1、3-2 |
| FR-2.2 | プレイリストの名前を変更できる | 3-2 |
| FR-2.3 | プレイリストを削除できる。削除前に確認が表示される（※確認は補足） | 3-2 |
| FR-2.4 | 検索タブ（FR-6.1）で検索した曲、またはカート（FR-1.12・FR-1.13）にためた曲を追加する際、追加先のプレイリストを選ぶモーダル／画面が表示され、選んだプレイリストに曲が追加される。プレイリスト詳細画面から検索へ遷移する導線はない | 3-2、8-1（CR-006により変更） |
| FR-2.5 | プレイリストから曲を削除できる | 3-2 |
| FR-2.6 | すでにプレイリストにある曲は「追加済み」と表示され、重複して追加できない。重複の判定は曲IDが同じ場合のみで、別収録版（シングル版とアルバム版など）は別の曲として追加できる | 3-3、9-2 |
| FR-2.7 | 1つのプレイリストに登録できる曲数に上限がない | 3-4 |
| FR-2.8 | アプリ起動後の最初のタブは「プレイリスト」（FR-6.1）であり、その中の最初の画面はプレイリスト一覧である | 6-1（CR-006と整合） |
| FR-2.9 | プレイリスト一覧から詳細画面を開ける。詳細画面に曲の一覧が表示される（※補足） | 6-2 |
| FR-2.10 | 再生操作と再生中の曲の表示は、プレイリスト詳細画面の中にまとめて表示され、再生専用の画面への遷移はない。詳細画面から離れた場合は、画面下部の常時表示ミニプレイヤー（FR-4.16）に表示が引き継がれる | 8-2（CR-003により一部変更） |
| FR-2.11 | プレイリスト詳細画面の曲一覧は、既定でアーティスト名順に並んで表示される。同一アーティスト内は、曲を追加した順で並ぶ。この並び順は表示のみに適用され、再生順（ランダム再生、FR-4.2〜FR-4.4）には影響しない | CR-004 |

### FR-3 保存
| ID | 基準 | 根拠 |
|---|---|---|
| FR-3.1 | プレイリストは端末内に保存され、ログインなしで利用できる | 5-1、7-1 |
| FR-3.2 | 保存するのは曲の識別情報のみで、曲名・ジャケット等は表示時に最新情報を取得する | 5-3 |
| FR-3.3 | 取得できなくなった曲（配信終了・試聴音源なし等）があっても、プレイリスト全体の表示・再生は失敗せず、その曲は再生時にスキップされ、利用者に分かる形で示される（※表示は補足）。端末がオンラインなのに1曲だけ取得できない場合も同様に、その曲をスキップして次へ進む | 5-3、9-4 |

### FR-4 再生
| ID | 基準 | 根拠 |
|---|---|---|
| FR-4.1 | プレイリストの詳細画面を開き、再生操作をすると連続再生が始まる（一覧のワンタップ再生は不要） | 6-2、8-2 |
| FR-4.2 | 再生順は再生を開始するたびにランダムに決まる | 憲章 決定事項、4-1 |
| FR-4.3 | 全曲が一巡するまで、同じ曲は再生されない | 4-1 |
| FR-4.4 | 一巡したら自動で再シャッフルして再生を続ける。曲が2曲以上ある場合、再シャッフル直後に、直前に再生した曲が続けて再生されない（※後半は補足） | 4-1、4-4 |
| FR-4.5 | 各曲は試聴音源（約30秒）を最後まで再生する | 4-2 |
| FR-4.6 | 1曲が終わると、操作なしで次の曲へ自動的に進む | 憲章、4-3 |
| FR-4.7 | 曲の切り替わりは2秒のクロスフェードで行われ、無音区間が生じない（優先度：中。NFR-4.5の画面オフ再生と両立しない場合は、クロスフェードを省略する） | 4-3、憲章 決定事項 |
| FR-4.8 | 一時停止と再開ができる | 4-5 |
| FR-4.9 | 次の曲へスキップできる | 4-5 |
| FR-4.10 | 今回の再生で再生した曲の履歴をたどって、前の曲へ連続で戻れる。一巡をまたいでも戻れる。履歴の先頭では何も起きず、戻るボタンは押せない表示になる | 4-5、9-3、11-3 |
| FR-4.11 | プレイリスト詳細画面の再生表示に、再生中の曲のジャケット・曲名・アーティスト名が表示される | 4-6、8-2 |
| FR-4.12 | 画面を消した状態や他アプリ使用中も連続再生が続き、ロック画面・通知から一時停止・スキップ等の操作ができる | 4-7 |
| FR-4.13 | 再生中に端末がオフラインになったら一時停止し、通信が復帰したら再開できる（1曲だけ取得できない場合はFR-3.3のスキップに従う） | 4-8、9-4 |
| FR-4.14 | 曲が1曲のみのプレイリストは、その曲を繰り返し再生する。曲が0件のプレイリストは再生操作ができない（※補足） | ― |
| FR-4.15 | 再生中に3曲連続で曲の取得に失敗した場合は、再生を止めてエラーを表示する（3曲未満の連続失敗は、FR-3.3のスキップに従う） | 9-4、11-2（レビューにより変更） |
| FR-4.16 | プレイリストの再生中に詳細画面から離れて（一覧に戻る・別のプレイリストを開く・検索タブに切り替える等）も、再生は止まらずに続く。画面下部に、再生中の曲のジャケット・曲名・アーティスト名と、一時停止/再開・次への操作を備えた、常時表示のミニプレイヤーが表示される。この継続再生・ミニプレイヤー表示は、アルバムの一時再生（FR-1.11）にも適用される | CR-003、CR-007 |
| FR-4.17 | ミニプレイヤーをタップすると、再生中のプレイリスト詳細画面（アルバムの一時再生中はその再生元の画面）に遷移する | CR-003 |

## 2. 非機能要件

### NFR-1 性能
| ID | 基準 | 根拠 |
|---|---|---|
| NFR-1.1 | 検索を実行してから3秒以内に結果が表示される（Wi-Fi・モバイル回線のどちらでも） | 2-1 |
| NFR-1.2 | プレイリスト詳細画面で再生操作をしてから、3秒以内に最初の曲の再生が始まる | 6-2 |
| NFR-1.3 | 曲の切り替わりで無音区間が生じない（クロスフェードで連続する。NFR-4.5により省略される場合は対象外） | 4-3 |

### NFR-2 信頼性・継続再生
| ID | 基準 | 根拠 |
|---|---|---|
| NFR-2.1 | 20曲のプレイリストを、最初から最後まで途中で止まらずに再生できる（所要時間の目安：クロスフェードありの場合は約9分22秒＝20曲×30秒−クロスフェード19回×2秒、クロスフェードを省略した場合は約10分＝20曲×30秒） | 4-8 |
| NFR-2.2 | 通信断（端末のオフライン）は許容される例外とし、FR-4.13の動作（一時停止→復帰後に再開）に従う | 4-8、9-4 |
| NFR-2.3 | 通信エラー時（検索・曲情報の取得）は、失敗したことが利用者に分かる表示が出て、アプリが操作不能にならない（※補足） | 1-3 |

## 3. 受入テストの実施条件（案）
- 端末：利用者本人のGalaxy S26（Android 16）、Chrome（最新版）
- 回線：Wi-Fiとモバイル回線の両方
- 曲データ：20曲以上のプレイリストを用意して確認する（NFR-2.1、FR-4.3、FR-4.4）
- 早期確認：画面オフ・バックグラウンドでの連続再生は必須要件（NFR-4.5）。PWAの制約に左右されるため、最小版の段階で最初に検証する。クロスフェード付きで通らない場合は、クロスフェードなしで画面オフ再生が成立するかを確認する
- 曲データ（CR-001〜CR-008分の追加）：検索結果が26件以上になるキーワード（FR-1.10）、アルバムを複数持つアーティスト・複数曲を持つアルバム（FR-1.9、FR-1.11）、アーティスト名が異なる曲を含むプレイリスト（FR-2.11の並び順確認用）を用意する
