# 開発計画（第2弾）：CR-001〜CR-008の実装

作成日：2026-09-27
根拠：acceptance-criteria.md（FR-1.8〜FR-1.13、FR-2.4改訂、FR-2.11、FR-4.16〜FR-4.17、FR-2.10改訂、FR-5.3、FR-6.1、NFR-3.4）、acceptance-test-cases.md、change-request-form.md（CR-001〜CR-008）
実装言語：素のJavaScript（HTML/CSS/JavaScriptのみ、フレームワーク・ビルド環境なし。plan.mdと同じ方針を継続）
位置づけ：plan.md（フェーズ0〜6、初回リリース分）は完了済みの実装として維持し、本ドキュメントはその上に追加・改修する「フェーズ7以降」の計画です。plan.md自体は書き換えず、本ドキュメントを別紙として扱います。

## この計画の考え方
- 今回のCR-001〜CR-008は、**「検索画面をメドレーから独立させる」（CR-006）**と**「再生をメドレー詳細画面のライフサイクルから切り離す」（CR-003）**という、既存実装の前提を変える2つの構造変更を土台にしています。他のCR（検索方式の拡張、無限スクロール、アルバム一時再生、カート）は、この2つの土台の上に乗る機能なので、先に着手します。
- 見た目の変更のみで依存の少ないもの（アーティスト順ソート＝CR-004、アイコン化＝CR-002）は、構造変更のあとに仕上げとして行います（アイコン化は特に、ミニプレイヤー等の新規UIも対象に含めるため、UIが出そろってからの方が手戻りが少ないと判断）。
- フェーズ番号はplan.mdの続き（フェーズ7〜）としています。

## 過去のplan.md（フェーズ0〜6）からの影響・変更点

今回の変更は、以下の既存実装の前提を書き換えます。着手前に必ず確認してください。

| 対象ファイル | 現状（plan.mdフェーズ2・3・4の実装） | 今回変更が必要な理由 |
|---|---|---|
| `js/app.js` | `showList` / `showDetail` / `showSearch` の3画面を直接呼び出す遷移モデル。`showSearch(medleyId)` は特定のメドレーIDに紐づいて開き、`disposeCurrentPlayer()` が画面遷移のたびに呼ばれ、詳細画面を離れると再生が破棄される | CR-006によりタブ構成（メドレー／検索）に再設計が必要。CR-003により、詳細画面を離れてもプレーヤーを破棄しない設計に変更が必要（フェーズ7・8） |
| `js/views/search-view.js` | `renderSearchView` は `onAdd`/`isDuplicate` を通じて、呼び出し側（app.js）があらかじめ決めたメドレーIDに対して追加・重複判定を行う設計 | CR-006により、検索画面はどのメドレーからも独立して開くため、追加時に追加先メドレーを選ぶ導線が必要（フェーズ7） |
| `js/views/medley-detail-view.js` | 「＋曲を追加」ボタンから`onAddTrack`で検索画面へ遷移する導線（FR-2.4旧版）、再生パネルを詳細画面内にのみ表示（FR-2.10旧版） | 「＋曲を追加」導線はCR-006で廃止。再生パネルとミニプレイヤーの表示切り替えの結線が必要（フェーズ7・8） |
| `js/medley-player.js` | メドレー（保存済みデータ）の再生を前提にした構成。生成は`app.js`の`onStartPlayback`から都度行われる | CR-007のアルバム一時再生でも同じ再生ロジックを流用する。メドレーに紐づかない一時的なトラック配列でも動かせるよう、呼び出し側のインターフェースを確認・調整（フェーズ10） |
| `js/search-api.js` | `buildSearchUrl`は`limit=25`固定、曲名・アーティスト名のみをAPIクエリに渡す設計 | CR-001でアルバム名を対象に追加（クライアント側フィルタ）、CR-005でoffset付きの追加取得に対応、CR-001の段階検索用に別エンティティ（アーティスト・アルバム）の検索関数を追加（フェーズ9） |
| `js/storage.js` | メドレー（IndexedDB）のみを保存対象とした設計 | CR-008のカート（FR-1.12、NFR-3.4）を保存する仕組みを追加（フェーズ10） |
| Unitテスト（`test/*.test.js`） | 画面（views）はUnitテスト対象外の方針（plan.mdの合意事項）。既存のUnitテストは`medleyId`に依存する画面ロジックを直接検証していない | 既存Unitテストの前提は崩れないため、大きな書き換えは不要。新規ロジック（段階検索・カート・並び替え等）にのみ、フェーズごとにUnitテストを追加する |
