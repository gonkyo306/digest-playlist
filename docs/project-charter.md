# プロジェクト憲章：お気に入り曲のダイジェスト・メドレーアプリ

作成日：2026-09-27
ステータス：企画段階（仕様は相談しながら決定）

## 1. 目的
Apple Musicで聴いている好きな曲を集めて、メドレーのように連続で聴けるようにする。曲順は再生のたびにランダムとする。
個人利用（自分）が目的で、ストア公開はしない。

## 2. 利用者
- 自分（Androidユーザー）

→ Androidで使えることが必須条件。iPhoneは対象外。

## 3. 利用シーン
通勤中や家事の合間に、アプリを開いてお気に入りのメドレーをすぐ再生する。
気分に合わせて曲を追加・削除して、メドレーを育てていく。再生のたびに曲順が変わるので、毎回違う流れで楽しめる。

## 4. 主な機能（現時点の想定）
1. 曲を検索して、メドレーに追加・削除できる
2. メドレーの曲を、毎回ランダムな順番で自動連続再生できる（手動の並べ替えは不要）
3. 作ったメドレーを保存し、いつでも呼び出せる

## 5. 曲データの方針
- Appleが無料で公開している試聴音源（約30秒）を利用する
- 曲全体ではなく、各曲の「ダイジェスト」をつなぐ形になる

## 6. 制約・前提
- ストア公開はしない（個人利用のみ）
- Androidのみ対応（iPhoneは対象外）
- 対象端末：Galaxy S26（Android 16）、Chrome
- PWAはGitHub PagesにHTTPSで配置し、URLを知っていれば誰でも開ける（アクセス制限なし）
- 実装言語は素のJavaScript（HTML/CSS/JavaScriptのみ、ビルド不要）とする
- 細かい仕様はこれから相談しながら決める

## 7. 進め方
1. 全体像と進め方の提案（本ドキュメントの次のステップ）
2. 仕様の相談・決定
3. 最小版（検索 → 追加 → ランダム連続再生）の作成
4. 保存機能の追加
5. 自分の端末での実利用と改善

## 8. 決定事項の記録
- 2026-09-27：曲順は毎回ランダムで良い（手動での並べ替え機能は作らない）
- 2026-09-27：画面オフ・バックグラウンドでの連続再生は必須要件とする。クロスフェードは優先度を下げてよく、両立しない場合は画面オフ再生を優先してクロスフェードを省略する。それでも画面オフ再生が難しい場合は、Androidネイティブアプリへの切り替えを検討する（要相談）
- 2026-09-27：受入基準の測定条件は「Wi-Fi・モバイル回線のどちらでも動作する」とする
- 2026-09-27：外部への通信の範囲は、配信元（GitHub Pages）への通信を除いて定義する
- 2026-09-27：再生中の曲取得失敗は、3曲連続で失敗した場合に再生を止めてエラー表示とする（3曲未満はスキップして継続）
- 2026-09-27：実装言語は素のJavaScript（フレームワーク・ビルド環境なし）とする
