# 受入テストケース一覧：お気に入り曲のダイジェスト・プレイリストアプリ

作成日：2026-09-27
更新日：2026-09-28（acceptance-criteria.mdのCR-030〜CR-035反映に合わせてテストケースを追加・更新。タブ再タップでのリセット、検索結果行の表示順、曲タップでの再生開始、Apple Music風ヘッダー、プレイリストの改名・削除アイコンの移設に伴う項目を追加。新規・変更分は未実施＝結果欄は空欄）
根拠：acceptance-criteria.md（機能要件 FR、非機能要件 NFR）
表記：「対応基準」は acceptance-criteria.md の ID です。「結果」欄は実施時に ○／×／備考 を記入してください。

**注記**：グループ②（検索・プレイリスト管理・再生操作）の項目は、実機（Galaxy S26）ではなくPCのブラウザ（Chrome、開発用の built-in browser）でClaudeが事前確認した結果です。ロジック面の妥当性は確認できていますが、実機での見た目・操作感・実際の音の確認は別途お願いします。特にTC-FR-4.13-1/4.13-2（オフライン）は、機内モードではなくJavaScriptのoffline/onlineイベントを直接発生させて確認したものです。

## 0. 実施条件

- 端末：Galaxy S26（Android 16）、Chrome（最新版）
- 配信：GitHub Pages の URL（HTTPS）から開く
- 回線：Wi-Fi とモバイル回線の両方（回線を指定していないテストは、Wi-Fi で実施）
- 事前に用意するもの：
  - プレイリスト A（20曲以上、曲名・アーティストが異なる曲）
  - プレイリスト B（1曲のみ）
  - プレイリスト C（0曲）
  - プレイリスト D（TC-FR-2.4-2/2.4-3の「前回の追加先」確認用に、もう1つ）
  - 試聴音源がない曲（FR-1.4 用）
  - 同じ曲の別収録版（シングル版とアルバム版など、FR-2.6 用）
  - 複数のアルバムを持つアーティスト、複数曲を持つアルバム（FR-1.9用）
  - 曲・アーティスト・アルバムが混在してヒットするキーワード（FR-1.8、TC-FR-1.2-2用）
- 先行して実施するテスト：TC-NFR-4.5-1、TC-FR-4.12-1（画面オフ・バックグラウンドでの連続再生は必須要件。PWA の制約に左右されるため、最小版の段階で最初に検証する。クロスフェード付き（TC-FR-4.7-1）で通らない場合は、クロスフェードなしで画面オフ再生が成立するかを確認する（TC-NFR-4.5-2））
- 開発者ツールを使うテスト（TC-FR-3.2-1、TC-FR-3.3-1、TC-FR-3.3-2、TC-NFR-6.2-1）は、PC の Chrome から端末をリモートデバッグして実施する

## 4. 優先度に関する補足
- 画面オフ・バックグラウンドでの連続再生（NFR-4.5）は必須要件です。TC-NFR-4.5-1（クロスフェード付き）が最優先の確認事項です。
- クロスフェード（FR-4.7）は、画面オフ再生と両立しない場合に優先度を下げてよい項目です。その場合、TC-FR-4.7-1・TC-NFR-1.3-1は不合格でも受入不可とはしません。TC-NFR-4.5-2でクロスフェードなしの画面オフ再生を確認してください。
- 再生中の曲取得失敗は、3曲連続で失敗した場合のみ停止・エラー表示とします（TC-FR-4.15-1、TC-FR-4.15-2）。2曲までの連続失敗はスキップして継続します。
- クロスフェードを省略してもなお画面オフ再生が成立しない場合は、Androidネイティブアプリへの切り替えを検討する必要があります（要相談。project-charter.md参照）。
